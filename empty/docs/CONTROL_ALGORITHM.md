# 步进电机位置模式 + 钢球视觉闭环控制算法

## 1. 系统概览

```
上位机视觉 (≈30fps)
    │
    │ UART0 RX 中断 → module/vision：$BALL 报文解析
    ▼
α-β 滤波器：从噪声像素测量中估计位置/速度
    │
    ▼
位置模式 PD 控制律：Kx·error − Kv·velocity → 绝对脉冲目标
    │
    ▼
静摩擦夹紧 (阈值型补偿，仅在确实卡住时介入)
    │
    ▼
    ├──→ 边缘保护 (球快滚出时回水平)
    │
    ▼
Emm42Robot_MoveAbsolute() → UART1 → Emm42 ID1 驱动器
    │
    ▼
摆杆升降丝杆 (导程 8mm/圈，3200 脉冲/圈，400 脉冲/mm)
    │
    ▼
摆杆角度变化 → 钢球在凹槽内滚动
    │
    ▼
上位机视觉捕获新位置 → 闭环
```

整个系统是 **位置外环**（视觉→球位置→摆杆目标脉冲），驱动器内部另有**速度环+位置环**（内环，出厂 PID 不动）。外环约 33ms 一帧全新绝对位置目标，覆盖上一条未走完的命令。

---

## 2. 为什么用位置模式而不是速度模式

### 2.1 速度模式的问题

速度模式下，控制量为 RPM（角速度）：

```
RPM → ∫ → 摆杆角度 → ∫∫ → 钢球位置
```

整条链路是**三阶系统**，纯 PID 的输出 RPM 对钢球位置来说是一个两次积分后的结果——任何 RPM 的误差都会在被积分放大成角度误差后再一次被积分放大成位置误差，极难镇定。此前速度模式的 `DEGRADED`（软降速）、`LOST`（硬急停）、`FAULT_DIRECTION`（方向发散保护）三层保护就是为了防止这种三阶系统在调参过程中失控——但这些保护一旦被偶发视觉丢帧触发，就会在正常运动中"突然停车"，打断调参观测。

### 2.2 位置模式的结构优势

```
targetPulse (绝对脉冲位置) → 摆杆角度 → 钢球位置
```

控制量从 RPM 降为**目标绝对脉冲**，系统从三阶降为二阶（标准的球杆系统 `ball-and-beam`），外环只需经典 PD：

```c
targetPulse = LEVEL_TRIM_PULSE + SIGN × (Kx × errorPx − Kv × velocityPxPerSec)
```

二阶系统的另一个重要好处是**位置模式结构上自带安全**：不发新命令时电机保持停在上次下发的绝对位置，不像速度模式那样一直旋转。这意味着保护逻辑可以大幅精简：丢帧时只需在 OLED 上标记 `B:LOST`，不需要下发硬急停来防止失控。

所有公开的开源 ball-and-beam 实现都用舵机或位置伺服直接给角度，没有一个把角速度当控制量——这不是巧合，是这个物理系统本身的特性决定的。

## 3. α-β 滤波器

### 3.1 用途

上位机返回的钢球 X 坐标（0~640px）带有约 30fps 的量化噪声和偶尔的单帧跳变。α-β 滤波器同时估计**平滑位置**和**线性速度**，为 PD 控制器提供干净反馈。

### 3.2 算法公式

- **预测**：
  ```
  x_pred[k] = x_filter[k-1] + v_filter[k-1] × dt
  ```

- **更新**：
  ```
  x_filter[k] = x_pred[k] + α × (z[k] − x_pred[k])
  v_filter[k] = v_filter[k-1] + β × (z[k] − x_pred[k]) / dt
  ```

其中 `z[k]` 是像素测量值，`α`（位置权重）和 `β`（速度权重）均为 `[0,1]` 常数。

### 3.3 参数说明

| 参数 | 当前值 | 效果 |
|------|-------|------|
| α | 0.70 | 位置跟踪速度；越大越相信测量（响应快但噪声大），越小越相信预测（平滑但有滞后） |
| β | 0.08 | 速度估计响应；越大速度跟踪越快，但对测量噪声更敏感 |

α=0.70 偏重跟踪（响应快于平滑），β=0.08 保守（速度避免被像素级抖动带跑）。调参时：如果位置输出在目标附近高频抖动，先降 α（如 0.60）；如果速度估计明显滞后于实际运动（导致 Kv 的效果打折扣），适当升 β（如 0.12）。

### 3.4 复位与恢复

- `AlphaBetaFilter_Reset()` 清空内部状态，下一次 `Update` 直接以测量值作为位置、速度置零。
- 视觉丢失后恢复的第一帧只重建位置（速度置零），第二帧才用真实帧间隔恢复速度估计和控制输出——避免长时间断帧后恢复时产生速度尖峰。

### 3.5 dt 的时间来源

- **帧间隔 dt** 使用相邻两帧有效 X 之间的实际 FreeRTOS tick 差，限制在 `[0.02s, 0.20s]` 范围内。
- `BALL_CTRL_NOMINAL_DT_SEC = 1/30s`：当没有上一帧时间戳（首次启动后第一帧）时使用的默认值。
- **控制任务周期 10ms**：BALLCTRL 每 10ms 轮询一次视觉快照，但只在 `sequence` 变化时才更新 α-β 和控制输出——10ms 不是视觉帧率，不要误用。

## 4. 位置模式 PD 控制律

### 4.1 核心公式

```c
rawError  = targetPx − filter.position;       /* 位置误差 (px)，传感器方向：X 增大 = 球向右 */
pulseDelta = Kx × rawError − Kv × velocity;   /* 纯 PD 输出 (脉冲) */

targetPulse = LEVEL_TRIM_PULSE + SIGN × round(pulseDelta);
Emm42Robot_MoveAbsolute(EMM42_ROBOT_LIFT, targetPulse, BALL_CTRL_POS_RPM, 0);
```

### 4.2 为什么是纯 PD（没有 I）

**绝对位置模式本身没有稳态误差问题**：驱动器会把丝杆精确停在每次下发的目标脉冲位置，不存在速度模式下"RPM 积分才能维持位置"导致的静差。唯一需要"补偿"的是静摩擦——但这属于阈值型非线性，不是线性稳态偏置，不能用 I 项处理（见第 5 节）。

### 4.3 Kv 在位置模式中的作用

Kv 不是位置模式必需的——位置命令本身不会"冲过头"。Kv 真正压的是**钢球惯性**：当摆杆改变角度、钢球开始在凹槽里加速时，即使位置误差已经减小到 0，钢球已有的速度仍会带它继续越过目标。Kv 项根据 `filter.velocity` 产生的反向脉冲能提前制动，抑制过冲。

**如果没有 Kv**：Kx 需要在误差>0 才能产生反向脉冲，但此时球已经越过目标、误差反向——表现就是标准的欠阻尼振荡（"冲过头→Kx 修正→再冲回来"）。

### 4.4 物理量纲换算

经题目六冒烟测试实测（10 圈 = 80mm）：

| 参数 | 数值 |
|------|------|
| 脉冲/圈 | 3200（16 细分出厂值） |
| 导程 | 8mm/圈 |
| 脉冲/mm | 400 |
| 杆长 | 250mm |
| 杆端升降 d | pulse/400 mm |
| sinθ | d / 250 |

有了这些数据后，Kx/Kv 可以做物理量纲换算：`Kx × errorPx` 产生的是"让摆杆倾斜到某个角度"所需的脉冲数。球杆系统的运动学由重力分量驱动：`a ≈ (5/7)·g·sinθ`，可以据此估算 Kx 的理论下限。

## 5. 静摩擦阈值补偿（Stiction Clamp）

### 5.1 问题本质

这是**阈值型非线性**，不是**线性稳态误差**：

```
钢球在凹槽里：倾角变化  →  倾角 < 阈值  →  球不动（静摩擦）
                       →  倾角 ≥ 阈值  →  球开始加速滚动
```

丝杆本身的间隙和钢球在凹槽内的滚动静摩擦共同构成了这个阈值——题目六阶梯测试实测约为 **3200~4000 脉冲**（即约 8~10mm 丝杆行程）。

### 5.2 为什么不能用 I 项

I 项在这种场景下是两个问题：

1. **延迟大**：I 项需要多个帧周期慢慢积分才能积累到足以突破阈值的量级，意味着钢球会在"僵住"的位置等半秒到一秒才开始动；
2. **冲破过冲**：当 I 项的积累终于达到阈值时，积累的额外积分量与阈值量叠加，使第一次"踹一脚"的幅度大于实际需要，钢球获取过量速度 → 过冲。

正确的处理：**既然已经用阶梯测试测出了精确阈值，直接把命令幅度顶到这个阈值**（保持符号方向不变），一步跨越静摩擦死区，不需要等待积分。

### 5.3 带持续时间的低速判定

关键约束：**只在实际卡住时介入，不在正常减速路过时误触发**。

```c
if (|velocity| ≤ STUCK_VELOCITY) {
    if (stuckStartTick == 0)
        stuckStartTick = now;
    else if (now - stuckStartTick ≥ STUCK_TIME_MS  &&  |pulseDelta| < STICTION_PULSE)
        pulseDelta = sign(pulseDelta) × STICTION_PULSE;  // 顶到阈值
} else {
    stuckStartTick = 0;  // 球在正常移动，重置计时
}
```

- `BALL_CTRL_STUCK_VELOCITY_PXPS = 5.0`：判定"基本没动"的速度下限；
- `BALL_CTRL_STUCK_TIME_MS = 150`：必须连续低速这么久才算卡住，不留这个时间门限的话，球快到目标前的正常减速瞬间就被误判成卡住 → 满幅夹紧 → 推走 → 减速 → 再被夹紧 → 持续振荡。
- 在以下情况重置 `stuckStartTick = 0`：速度恢复正常、误差进入死区（`SETTLE_DEADBAND_PX`）、K4 重新启动、帧丢失进入 LOST。

### 5.4 死区（Deadband）

`BALL_CTRL_SETTLE_DEADBAND_PX = 3.0`：误差小于 3px 时 `pulseDelta = 0`，不介入夹紧也不做修正。在这个量级下钢球的推不动不叫"精度损失"，而是物理极限——这么小的倾角下静摩擦本来就推不动球。

## 6. Emm42 位置模式协议详述

### 6.1 帧格式（§6.3.1）

```
地址 + 0xFD + 方向 + 速度H + 速度L + 加速度 + 脉冲H + 脉冲MH + 脉冲ML + 脉冲L + 绝对/相对 + 同步 + 0x6B
```

**各字节含义**：

| 字段 | 说明 |
|------|------|
| 地址 | 设备地址 1/2/3 |
| 0xFD | 位置模式命令字 |
| 方向 | `00`=CW, `01`=CCW；绝对模式下表示目标位置的符号 |
| 速度H/L | 目标转速，大端 2 字节，单位 RPM |
| 加速度 | 0=瞬时到位；非 0=曲线档位，见下方说明 |
| 脉冲H~L | 脉冲数，大端 4 字节，单位取决于细分（出厂 16 细分=3200 脉冲/圈） |
| 绝对/相对 | `00`=相对, `01`=绝对 |
| 同步 | `00`=不等待同步立即执行, `01`=等待同步 |
| 0x6B | 帧尾校验 |

### 6.2 加速度曲线公式

手册 §6.3.1：

```
t2 − t1 = (256 − acc) × 50us  每升 1 RPM
```

- `acc = 0`：不用曲线，**直接按设定速度**运行（最快响应）；
- `acc = 180`：每升 1RPM 需要 `(256−180)×50us = 3.8ms`，升到 200RPM 需要约 760ms。

**关键经验**：这个曲线档位只在**持续巡航**场景下有效（如题目二轮子——前后帧目标转速差小，曲线不需要从 0 重新爬升）。对于**BALLCTRL 每约 33ms 刷新一次全新绝对目标**的场景，曲线还没爬到目标 RPM 就被下一帧打断重新规划，实际能达到的速度远低于目标值——acc=150 时实测反而比 acc=0"明显慢得多"。**此类场景必须用 acc=0**。如果后续需要平滑运动，应该在软件层面对目标脉冲做低通滤波，而不是依赖驱动器曲线。

### 6.3 堵转保护

触发条件（**三个同时满足**）：

| 条件 | 默认阈值 |
|------|---------|
| 转速 | < 40 RPM |
| 相电流 | > 2400 mA |
| 持续时间 | > 4000 ms |

丝杆低速顶到机械限位时三条全部命中。**触发后所有速度/位置命令返回 `E2`，电机纹丝不动**——表现是"第一次能动，之后怎么发都不动"。解除命令：`0x0E 0x52`。

BALLCTRL 和题目六在启动前都会先发一次清除堵转保护（`Emm42Robot_ClearClogProtection`），清掉上轮运动残留的堵转标志。

### 6.4 位置清零

`0x0A 0x6D`：将驱动器内部的位置计数器、位置误差和脉冲数全部清零。断电不保留，每次上电需重新建立原点。

### 6.5 读位置（`0x36`）的单位陷阱

`0x36` 返回的是**编码器原始角度**（65536 = 一圈），不是脉冲数。与位置命令的换算系数为 20.48 倍：

```c
pulses = raw_value × 3200 / 65536;
```

`0x33`（目标位置）、`0x37`（位置误差）同理。

### 6.6 到位判定

- 读 `0x3A`：bit1 = 到位标志；
- 或将驱动器 Response 菜单设为 `Reached`/`Both`，到位后主动回 `地址+FD+9F+6B`；
- 位置到达窗口默认 1 = 0.1°（约 0.9 脉冲 @16 细分），所以 1 脉冲的增量就能触发到位。

## 7. 零点策略

### 7.1 一次清零原则

位置模式的"原点"必须在人工摸平摆杆后建立。BALLCTRL 采用**只在本次 MCU 上电后第一次启动时清零**的策略：

```c
static bool hasZeroedSinceBoot = false;  /* 任务入口的函数级 static */

/* 使能完成后 */
if (!hasZeroedSinceBoot) {
    Emm42Robot_ResetPosToZero(EMM42_ROBOT_LIFT);
    hasZeroedSinceBoot = true;
}
```

这样设计的原因：调参过程中会反复用 K4 停/启，中途摆杆停在某个倾角上时并没有弹回水平——如果每次重启都重新清零，这个偶然偏移会成为新零点，目标位置累积漂移。**只有重新上电 MCU**（届时你会先重新摸平）才会建立新原点。

### 7.2 与 task6 的区别

| 场景 | 清零策略 | 原因 |
|------|---------|------|
| BALLCTRL 后台闭环 | 仅首次上电 | 反复调参时需要固定的参考系 |
| task6 冒烟测试 | 每次进入都清零 | 一次性工具，每次进题都可能摸了杆 |

这是一个通用的设计模式归类法：**"一次性测试工具"**和**"反复调参的常驻线程"**应该用不同的参考系策略，不能混用默认值。

## 8. 保护逻辑设计哲学

### 8.1 控制范式决定保护需求

保护逻辑**必须与当前控制范式匹配**，不能在换范式后继续沿用旧保护：

| 保护项 | 速度模式（旧） | 位置模式（新） |
|--------|-------------|-------------|
| DEGRADED（软降速） | 需要：防止 RPM 在丢帧后失控 | 不需要：不发新命令电机就停在原地，天然安全 |
| LOST 硬急停 | 需要：漂移几秒会碰到限位 | 不需要：停在最后有效目标上不会漂移 |
| 方向发散检测 | 需要：速度模式增益给反会指数发散 | 不需要：位置模式下增益给反只会慢速偏斜，肉眼可判断 |
| 边缘保护 | 保留（球的物理位置边界不变） | **改为回水平，不是急停**；保留使能以便观察 |

BALLCTRL 位置模式版本仅保留两处主动干预：
1. **边缘保护**：球跨过 `[20px, 620px]` 边界时命令丝杆回水平 → `FAULT_EDGE`，等其他 K4 处理；
2. **K4 主动停止**：急停 → 失能 → `OFF`。

所有"偶发丢帧"场景只影响 OLED 显示标签，不下发任何停止命令，确保正常运动不会被保护逻辑打断。

### 8.2 "持续性门限"是一个可复用的设计模式

项目中两处都用到了这个模式：

| 场景 | 门限 | 作用 |
|------|------|------|
| HOLDING 判定 | 500ms | 持续满足低速+靠近中心才算真正稳定 |
| 静摩擦夹紧 | 150ms | 持续低速才算卡住，不是路过瞬间 |

命名可以统一为："检测到一个瞬时条件 → 不要立即做出攻击性干预 → 等待 `X_MS` 持续满足条件才判定为真"。这是防止误触发最基础也最有效的手段，应该成为所有"检测到异常就出手"类型的保护逻辑的默认组成部分。

## 9. 关键经验总结

### 9.1 ACC 参数的场景适用性

| 命令模式 | 适用 acc | 原因 |
|---------|---------|------|
| 持续巡航（题目二轮子，前后帧目标转速差小） | 非 0 如 180 | 曲线平滑，不需要从 0 爬升 |
| 每帧全新绝对目标（BALLCTRL 位置外环，33ms 刷新） | **必须 0** | 曲线来不及爬就被下一帧打断 |
| 一次性大行程（题目六冒烟测试，长时间等一个目标走完） | 0 或非 0 均可 | 有完整的时间让曲线走完，按需选择 |

**判断范式**："这个命令模式，从一个位置/速度到下一个之间，有没有足够的连续时间让曲线跑完？"——没有就 ACC=0。

### 9.2 静摩擦阈值 vs 稳态误差

| 现象 | 判断方法 | 处理 |
|------|---------|------|
| 稳态误差 | 球停在偏目标一个固定像素的位置，误差稳定不变化 | 调 LEVEL_TRIM_PULSE |
| 静摩擦卡死 | 球在离目标还有一段距离就完全僵住，丝杆也不动了 | 阈值型夹紧（不要用 I 项） |
| 欠阻尼振荡 | 球在目标附近来回晃动，幅度逐渐衰减 | 加大 Kv 或降低 Kx |
| 夹紧误触发振荡 | 突然被"猛推"一下，然后回弹再被推，等幅振荡 | 增加 STUCK_TIME_MS |

### 9.3 位置模式的"安全"不是鼓励不加保护

虽然位置模式结构上比速度模式安全，但仍然需要：
- **行程限位**（当前尚未实测，缺 `BALL_CTRL_MAX_PULSE` 常量）；
- **边缘保护**（已经实现）；
- **上电前人工摸平**（依赖人工步骤，不是软件保护——需要培训操作者）。
