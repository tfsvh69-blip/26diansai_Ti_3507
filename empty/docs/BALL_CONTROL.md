# 钢球 X 位置闭环设计与调试指南

> ⚠️ **2026-08 机构由"丝杆升降+连杆"换成"电机直驱曲柄摇臂"（±90° 内旋转）**。
> 本文档第 2 节及以后的具体标定数据（脱离阈值 B、真实水平 L、Kx/Kv 物理系数
> 0.171 等）都是针对**旧丝杆机构**测出来的，直驱摇臂下已经失效，仅作历史参考
> 和标定方法论示例，不能直接套用。**当前机构的重新标定哲学、实操调参步骤、
> 现象→参数对照表见 [CONTROL_ALGORITHM.md](CONTROL_ALGORITHM.md) §10**；本文档
> 第 1 节（当前目标/参数隔离/题目状态）已按新机构更新，第 6 节协议细节、
> α-β 滤波公式等机构无关内容仍然准确。

## 1. 当前目标

MCU 复位或重新上电后保持原有 OLED 菜单界面，ID1 处于失能状态；开机会先经
`app/app_lift_homing.c` 的 `AppLiftHoming_RunAtBoot()` 自动归零（见
`CLAUDE.md`「ID1 开机自动归零」），不再需要人工把杆摆到目视水平。菜单态首次按 K4
使用模块默认 `BALL_CTRL_*` 参数请求 `X=350` 单点验证，右侧 OLED 的 `X:` 与 `B:` 分别
反馈实测位置与闭环状态；闭环运行时再次按 K4 安全停止。题目三、题目四仍各自的 `OnEnter`
经 `AppBallControl_RequestTargetWithProfile()` 按需启动独立 profile；题目三使用中心等待目标及独立的左右摆动目标，
题目四使用 `T4_BALL_TARGET_X_PX`，均通过 UART1 **位置模式**控制 Emm42 ID1 摆杆曲柄摇臂
机构；题目退出时请求安全停止、急停并失能 ID1。

闭环作为后台能力运行，不绑定某一道题。后续题目只需调用：

```c
AppBallControl_RequestTarget(targetPx);
```

即可用菜单默认参数更新目标位置；调用 `AppBallControl_RequestStop()` 可请求安全
退出。需要独立调参的题目可调用：

```c
AppBallControl_RequestTargetWithProfile(targetPx, &profile);
```

配置会在投递时复制到控制线程，后续目标更新可继续传同一配置。题目三以
`BALLCTRL` 控制 ID1 完成左右摆球，ID2/ID3 只使能并保持 0 RPM；题目四在控制
ID2/ID3 循迹的同时，经 `BALLCTRL` 控制 ID1 保持钢珠位置。题目三与题目六使用 ID1，
进入前会先等待后台闭环释放 ID1，避免两个控制源争抢同一电机。

### 1.1 控制参数隔离规则

可复用的是 `BALLCTRL` 执行器、α-β/PD 算法实现和 UART1 协议出口；**可调参数绝不复用**。
不同任务的机械负载、目标位置、行驶扰动和验收精度不同，直接共用一组增益、死区、滤波、
静摩擦阈值、位置模式速度或保持条件会使一个任务的调参破坏另一个任务。

当前参数组如下：

| 使用场景 | 私有参数组 | 调参影响范围 |
|---|---|---|
| 菜单 K4 单点验证的默认 profile（`AppBallControl_RequestTarget()` 用） | `BALL_CTRL_*` | 仅菜单 X=350 验证 |
| 任务三左右摆球 | `T3_BALL_*` | 仅任务三 |
| 任务四行驶平衡 | `T4_BALL_*` | 仅任务四 |

新任务即使先采用现有参数作为初值，也必须在自身 `taskN.c` 新建独立宏和
`AppBallControlProfile_t`，通过 `AppBallControl_RequestTargetWithProfile()` 按值投递；不得
引用或修改其他任务的参数宏。

### 1.2 题目六：启动加速度抬升前馈

题目六第二次 K3 后，轮子从 0 RPM 以 `T6_RAMP_RPM_PER_SEC` 爬升时，通过
`AppBallControl_SetLevelTrimOffset()` 临时叠加任务六私有的 `+40` 脉冲抬升偏置：前
150 ms 平滑抬升，加速段保持，达到 `T6_BASE_RPM` 后在 300 ms 内回到 0。该量用于抵消
小车启动加速度扰球，是前馈而非巡线 PID 或钢珠位置 PD 的 P/I/D 参数；仅影响
`task6.c`，停止闭环或触发 `FAULT_EDGE` 时自动清零并回到 profile 原水平点。

### 1.3 题目四：两段式启动 + 行驶中的钢珠平衡

ID1 位置零点由开机自动归零流程建立（见 `CLAUDE.md`「ID1 开机自动归零」），不再需要
人工在菜单页按 K4。**2026-08 新增两段式 K3 启动**：进题目先什么都不动（ID1 不闭环、
轮子不使能）；**第一次 K3** 才向 `BALLCTRL` 按值投递 `task4.c` 中的 `T4_BALL_*`
profile 和目标 `T4_BALL_TARGET_X_PX`，并等待后台进入 `RUNNING`/`HOLDING`（OLED 显示
`T4 B WAIT`）；**第二次 K3** 才使能 ID2/ID3 起步、开始循迹、开始录像。因此小车整个
行驶过程都由同一后台算法持续平衡钢珠；ID1 新视觉帧位置命令与轮子速度帧由 UART1
整帧互斥和至少 6ms 帧间隔串行化。任务四的缓停、自动完成后不停止 ID1，保持目标至 K4
退出；K4 收尾时才同时急停失能轮子并请求后台停止 ID1。

**`FAULT_EDGE` 自动恢复**：`BALLCTRL` 一旦因球触边进入 `FAULT_EDGE` 就会锁定在回
水平的位置，不会自行恢复（见第 6 节）。`Task4_OnLoop()` 每拍检测这个状态，一旦出现
就自动请求停止、等 `BALLCTRL` 回到 `OFF` 后重新以 `T4_BALL_*` profile 请求启动（新
状态 `T4_STATE_BALL_RECOVER_WAIT`，OLED 显示 `T4 B RECOV`），不需要用户手动退出
重进任务四。恢复完成时会先检查本次任务是否已经跑完（`s_runCompleted`，到达缓停或
终点保护的终止态时置位）：**已经跑完就直接停在终止态，不会被误判成还要继续循迹**——
这是修过一次真实 bug 后加的（终止态之前没有在 `OnLoop` 入口直接 `return`，会被恢复
握手意外拨回 `RUN`，表现为小车已停、蜂鸣器已响，OLED 秒表却还在走）；否则若轮子
已经起步，恢复后直接回到循迹，不重新走轮子使能时序。

**手动调参开关**：`task4.c` 顶部 `T4_MOTORS_DISABLED_MANUAL_TEST` 置 `1` 时轮子
不使能、不驱动，第二次 K3 也不会发车，只有后台 `BALLCTRL` 按 `T4_BALL_*` 保持钢球
在目标位置，配合用手推小车模拟前进/加减速扰动，专门调 `T4_BALL_*` 参数（OLED 显示
`T4 MANUAL`）；置 `0`（默认）才会执行完整的两段式启动+循迹+缓停流程。

`T4_BALL_*` 与 `T3_BALL_*`、菜单 `BALL_CTRL_*` 完全独立，互不影响；具体 Kx/Kv/
滤波/摩擦前馈/水平点/执行器参数数值以 `task4.c` 当前源码为准，调参方法论见
[CONTROL_ALGORITHM.md](CONTROL_ALGORITHM.md) §10。

### 1.4 题目三：左右摆球

`task3.c` 进题后先用 PA24 限位开关完成 ID1 回零并抬升到水平附近，ID2/ID3 仅使能为
0 RPM。`T3_BALL_CENTER_X_PX` 只用于 K3 前的中心保持；
`T3_BALL_LEFT_TARGET_X_PX`、`T3_BALL_MIDDLE_TARGET_X_PX` 与
`T3_BALL_FINAL_TARGET_X_PX` 分别独立设定三段目标。
抬升并位置清零后自动以 X=350 启动闭环并等待 K3，期间持续保持中心目标；按键后钢珠首次进入 230 的
`±T3_BALL_LEFT_ARRIVAL_BAND_PX` 即切 380，首次进入 380 的
`±T3_BALL_MIDDLE_ARRIVAL_BAND_PX` 即切 450；450 稳定 200ms 后结束。最终段达到 500 px
时重投 450 目标回拉，边缘故障仍按停止、释放、重新请求的握手恢复。所有参数是独立
`T3_*`/`T3_BALL_*`，与任务四、五互不影响。

**2026-07-31 由速度模式切到位置模式**：此前把 PID 输出直接当 ID1 的**速度**
下发，RPM 对摆杆角度是一次积分、球位置对摆杆角度又是二次积分，整链三阶，
纯 PID 极难镇定，表现为过冲、反复摆动。改为位置模式后，控制量降回**摆杆
角度**（每帧下发绝对目标脉冲），系统降为球杆系统标准的二阶对象，外环是
经典 PD：

```c
targetPulse = LEVEL_TRIM_PULSE + SIGN * (Kx * positionError - Kv * ballVelocity);
```

第 8 节列出的开源 ball-and-beam 实现全都是这个结构——用舵机或位置伺服直接
给角度，没有一个把角速度当控制量。

## 2. 30fps 视觉反馈的时间约束

上位机当前约 30 帧/秒（原设计假设 15Hz）：

```text
Tvision = 1 / 30s ≈ 33ms
```

`BALLCTRL` 每 10ms 检查一次快照，以降低新帧到达后的响应延迟，但只在
`xSeq` 改变时更新滤波器和控制输出，绝不能把 10ms 误当成视觉采样周期。
速度估计使用相邻有效 X 帧的实际 tick 间隔，限制在 `[BALL_CTRL_DT_MIN_SEC,
BALL_CTRL_DT_MAX_SEC]=[20ms, 200ms]`（下限比旧版 30ms 更松，避免 30fps
下偶发的稍快间隔被硬拉长、拉低速度估计）。

**位置模式下"无有效 X"不再需要主动急停**：没有新命令时电机保持在最后一次
下发的绝对目标位置，本身就是安全状态。因此：

- 连续两帧 `$X,NA`（`BALL_CTRL_NA_LOST_COUNT=2`）或 220ms 仍无有效 X
  （`BALL_CTRL_VISION_TIMEOUT_MS`）才判定为 `LOST`，且**只影响 OLED 显示**，
  不下发任何停止命令；
- 从 `LOST` 恢复要求连续两帧有效 X：第一帧重新初始化滤波位置并把速度置零，
  第二帧按真实帧间隔恢复控制输出，避免长时间断帧后产生速度尖峰；
- 唯一仍会主动下发命令的保护是边缘保护（球真的快滚出摆杆，见第 5 节）。

## 3. 软件结构

```text
UART0 RX ISR
    ↓
module/vision：校验并发布 X + xSeq
    ↓
BALLCTRL 10ms 线程：消费新 xSeq（NA/超时只标记状态，不打断已下发目标）
    ↓
α-β 滤波：估计 x_filter、v_filter
    ↓
局部 PD：pulseDelta = Kx·error − Kv·v_filter
    ↓
静摩擦夹紧（球基本没动且量级不足以克服静摩擦阈值时，顶到阈值打破僵局）
    ↓
targetPulse = LEVEL_TRIM_PULSE + sign×pulseDelta
    ↓
边缘保护（唯一仍主动下发命令的保护：命令回水平并锁定）
    ↓
module/emm42：UART1 整帧互斥 + 至少 6ms 帧间隔
    ↓
Emm42 ID1 绝对位置模式
```

控制命令使用长度为 1 的 FreeRTOS 覆盖队列，只保留最新目标；状态通过临界区
保护的只读快照发布给 OLED。任务层不直接访问闭环内部变量。

## 4. 当前控制参数

参数集中在 [app/app_ball_control_task.c](../app/app_ball_control_task.c) 顶部。

| 参数 | 初值 | 作用 |
|---|---:|---|
| `BALL_CTRL_OUTPUT_SIGN` | `+1` | 最终机构/相机极性，方向错时改成 `-1`；不要改 `emm42_robot.c` 的全局方向标定表 |
| `BALL_CTRL_KX_PULSE_PER_PX` | `25.0` | 位置误差到目标脉冲的比例增益（以源码当前值为准，会持续调） |
| `BALL_CTRL_KV_PULSE_PER_PXPS` | `9.0` | α-β 速度制动增益；用于压制接近目标时的过冲 |
| `BALL_CTRL_LEVEL_TRIM_PULSE` | `0` | "目视水平"到"物理平衡点"的补偿偏置，静置观察漂移方向后再调 |
| `BALL_CTRL_SETTLE_DEADBAND_PX` | `5.0` | 到位保持精度；误差在此范围内回水平且不触发静摩擦补偿，避免把已满足精度的钢球再次推出目标区 |
| `BALL_CTRL_STICTION_PULSE` | `3600.0` | 题目六阶梯测试实测的钢球静摩擦阈值（3200~4000 脉冲取中间值），球没动且算出来的量级不到这个数就直接顶上去 |
| `BALL_CTRL_STUCK_VELOCITY_PXPS` | `6.0` | 判定"球基本没在动"的速度门限，只有低于此值才允许静摩擦夹紧介入，球已经在动时不打断 Kv 的正常减速 |
| `BALL_CTRL_STUCK_TIME_MS` | `150` | 低速状态要持续这么久才算"真的卡住"，不是正常减速路过低速的一瞬间；没有这个时间门限会把"快到目标前 Kv 正常刹车导致的瞬间低速"也误判成卡住，见下方说明 |
| `BALL_CTRL_POS_RPM` | `200` | 位置模式巡航转速上限；30（题目六标定测试用的保守值）实测太慢，约只有 4mm/s 丝杆线速度，已提到 200 起步测试 |
| `BALL_CTRL_POS_ACC` | `0` | **必须用 0（瞬时）**：曾照搬题目二轮子的经验改成 150，结果实测反而更慢——手册公式"每升1RPM需要(256-acc)*50us"，acc=150 爬到 200RPM 要 1 秒多，但每 33ms 就刷新一次新绝对目标，曲线还没爬起来就被打断，效果远不如瞬时。题目二 acc=180 有效是因为持续巡航、前后帧目标差小，跟这里"每帧全新绝对目标"的场景不通用，见下方说明 |
| `BALL_CTRL_FILTER_ALPHA/BETA` | `0.70/0.08` | α-β 位置/速度滤波参数 |
| `BALL_CTRL_VISION_TIMEOUT_MS` | `220ms` | 无有效 X 判定 `LOST` 的硬超时（纯 UI，不再停车） |
| `BALL_CTRL_NA_LOST_COUNT` | `2` | 连续 NA 判定 `LOST` 的帧数（纯 UI） |
| `BALL_CTRL_HOLD_POSITION_PX/VELOCITY_PXPS/TIME_MS` | `5.0/10.0/500ms` | `HOLDING` 显示判定，仅影响 OLED，不影响控制 |
| `BALL_CTRL_SAFE_X_MIN/MAX_PX` | `20/620` | 边缘保护像素范围，唯一仍会主动下发命令的保护 |

**v1 按用户要求不加任何输出限幅、深度保护或抖动抑制**（无 I 项、无方向发散
检测、无软降速），先看原始表现，再一起边看边调。真实风险：增益给大了可能把
丝杆命令到超出实际机械行程的位置，行程限位以后测出来了再补一个类似 task6 的
`BALL_CTRL_MAX_PULSE` 常量。

**关于位置模式的 `acc` 参数：这个每帧刷新目标的场景必须用 `acc=0`**。2026-07-31
一度照搬题目二轮子"acc=0 会抖动、改非0曲线解决"的经验，把 `BALL_CTRL_POS_ACC`
改成 150，结果实测反而"明显慢得多"。原因是手册的曲线公式"每升1RPM需要
`(256-acc)*50us`"：`acc=150` 时爬到 `BALL_CTRL_POS_RPM=200` 需要 1 秒多，但
`BALLCTRL` 每约 33ms（视觉帧率）就下发一次新的绝对目标，曲线还没爬起来就被
下一帧打断重新规划，实际能达到的速度被摁在"帧周期÷每RPM爬升时间"这个很低的
量级——比 `acc=0` 瞬时给到目标 RPM 反而慢得多。**题目二的 acc=180 之所以有效，
是因为轮子是持续巡航、前后两帧目标转速差很小，不需要从 0 重新爬升；这里是
每帧一次全新的绝对位置目标，跟持续巡航的场景不通用，不能照搬**。如果确实需要平滑（而不是靠驱动器曲线），应该在软件层面对目标脉冲做斜率
限制，但题目二循迹早期就吃过这个亏——任务层再叠一层软件限速斜坡会把响应
拖得很慢，后来去掉改成 PID 输出直接下发才解决，位置模式大概率同理，先不要加。

**2026-07-31 加入静摩擦夹紧（唯一在 v1 基础上补的控制逻辑）**：题目六阶梯
测试实测钢球静摩擦阈值约 3200~4000 脉冲，而 `Kx=25` 在中等误差（几十~
一百多像素）下算出来的脉冲量远够不到这个阈值，丝杆会抬到一个不痛不痒的
高度就停住，球既不前进也不回落，卡死在原地——症状是"接近目标一段距离时
彻底僵住"，跟"稳态误差"是两回事。

**为什么不用 I 项而是直接夹紧到实测阈值**：I 项需要时间慢慢积分才能顶过
阈值，且冲破阈值那一刻会因为多余积累的积分量造成明显过冲；而阈值型静摩擦
非线性一旦被实测出准确数字，最直接的处理就是"不够就直接顶上去"（保留方向），
没有等待延迟、也不会有冲破瞬间的过冲。**只在球基本没在动
（`|velocity|≤BALL_CTRL_STUCK_VELOCITY_PXPS`）时才做这个夹紧**——球已经在动、
有速度时不介入，让 `Kv` 正常接管减速，否则会打断已经在收敛的运动。
`BALL_CTRL_SETTLE_DEADBAND_PX` 是实际到位保持区：误差在 ±3px 内即回水平，并且
重置静摩擦夹紧计时。这样视觉量化误差或正常的近端微小漂移不会触发 3600 脉冲的
大倾角补偿，把已满足精度的钢球再次推出目标区。

**⚠️ 2026-07-31 补了一个漏洞：低速判定必须加"持续时间"门限**。第一版夹紧
只要瞬时速度低于 `BALL_CTRL_STUCK_VELOCITY_PXPS` 就立刻满幅夹紧，结果实测
"目标附近 50px 内来回抖动、到不了"——因为 `Kx*error` 在误差小于
`BALL_CTRL_STICTION_PULSE/BALL_CTRL_KX_PULSE_PER_PX`（当前约 144px）时本来
就到不了阈值，而球快到目标前 `Kv` 正常刹车也会经过瞬间低速，这一刻就被误判
成"卡住"、猛地满幅一推，把快停稳的球重新推走，形成"以为卡住→满幅踹一脚→
冲过头→减速→又被当成卡住"的持续振荡。修复：新增 `BALL_CTRL_STUCK_TIME_MS`，
低速状态必须**连续**超过这个时长才真正判定为卡住，正常减速路过的瞬间低速
不会触发；球速度回升或误差回到死区内会立即重置这个计时。

## 5. 位置原点：只在本次上电后第一次启动时清零

**2026-08-01 起改为开机自动置零**：摆杆已加装 PA24 归零限位开关，`App_Init()`
在任何任务创建前调用 `app/app_lift_homing.c` 的 `AppLiftHoming_RunAtBoot()`
自动把 ID1 移动到指定的相对工作位置（正方向找开关→反向退让至释放→负方向移动
`LIFT_HOMING_TARGET_OFFSET_PULSES` 个脉冲），不再需要人工把杆摆到目视水平，
详见 `CLAUDE.md`「ID1 开机自动归零」。

1. **开机**：`AppLiftHoming_RunAtBoot()` 自动完成上述归零动作；
2. 题目三或题目四首次调用 `BALLCTRL`（经 `AppBallControl_RequestTargetWithProfile()`）
   时，其内部状态机在使能完成后自动发 `Emm42Robot_ResetPosToZero()`（协议
   `0x0A 0x6D`），把当前机械位置定义为绝对位置 0——只要 ID1 自开机归零后没被
   移动过，这个清零点就等于归零终点；
3. 之后所有绝对目标都以此为基准。

**只在本次上电后第一次启动时清零**（`AppBallControlTask_Entry` 内的函数级
`static bool hasZeroedSinceBoot`）：之后反复进出题目三/四调参不会重新清零，
沿用第一次建立的原点。这是有意的设计——调参过程中会反复停/启，中途摆杆可能
停在某个倾角上并没有弹回水平，如果每次重启都重新清零，这个偏移会被当成新
零点，误差跨轮次累积。只有重新上电 MCU（届时会先自动重新归零）才会建立新原点。

约束：**驱动器断电不保留多圈位置计数**，每次上电都要重做；失能不丢位置
（手册"电机转速和位置实时更新，使能不使能都可以"）。"目视水平"不等于
"物理平衡点"，`BALL_CTRL_LEVEL_TRIM_PULSE` 就是留给你在实车上微调这个偏置
的旋钮。

## 6. OLED 状态

菜单右侧第四行显示闭环状态：

| 显示 | 含义 |
|---|---|
| `B:OFF` | 未占用 ID1，上电默认状态 |
| `B:START` | 正在失能复位、使能、（首次）清零并等待驱动器稳定 |
| `B:WAIT` | ID1 已就绪，等待连续两帧有效 X（含首次启动和 LOST 恢复） |
| `B:RUN` | 正常闭环，持续下发新的绝对目标 |
| `B:HOLD` | 连续 500ms 满足中心位置与低速度条件，仍继续保持闭环（纯显示） |
| `B:LOST` | 连续两帧 NA 或有效 X 超过 220ms；**摆杆仍保持在最后一次有效目标，不会急停** |
| `B:EDGE!` | 钢球坐标到达画面安全边界 20/620px，已命令回水平并锁定 |

`EDGE!` 故障会保持 ID1 使能和已回水平的目标位置；运行态按 K4 退出当前题目会
请求急停并失能，状态回到 `B:OFF` 后才可再次启动（不会重新清零，见第 5 节）。

## 7. 上车调试顺序

### 阶段 A：只验证视觉

不进入题目三/四（不启动 `BALLCTRL`），连续观察 OLED：

1. 球在中心时 `X≈320`；
2. 向画面右侧移动时 X 增大，向左侧移动时 X 减小；
3. 静止波动先记录峰峰值；
4. 连续运行数分钟，确认无跳变、乱码和持续漂移；
5. 制造单次 `NA`，确认状态不受影响（v1 单帧 NA 不再改变任何显示或动作）；
   连续两次 `NA` 才进入 `B:LOST`；
6. 恢复识别后确认第一帧不产生新的闭环输出、第二帧回到 `B:RUN`。

未通过本阶段时不要使能 ID1。

### 阶段 B：首次启动与清零

1. **上电**：`AppLiftHoming_RunAtBoot()` 自动完成摆杆归零，无需人工调平；
2. 钢球放在目标附近（如 `X=280~350`）；
3. 进入题目三或题目四，确认 `B:START → B:WAIT → B:RUN`；这是本次上电后唯一一次清零；
4. 若中途需要反复进出题目调参，确认摆杆没有被你手动碰过——否则需要重新
   上电 MCU 才能重新归零、建立新零点。

### 阶段 C：确认最终控制方向

1. 观察钢球误差是否开始减小；
2. 若误差持续变大（摆杆明显往错误方向倾斜），按 K4 停止，把
   `BALL_CTRL_OUTPUT_SIGN` 从 `+1` 改为 `-1` 后重新编译；
3. 方向未确认前不增大 `BALL_CTRL_KX_PULSE_PER_PX`。

ID1 角色层只能说明"正 RPM＝连杆向下"，最终钢球方向还取决于连杆安装在摆杆
哪一端以及相机图像是否镜像，因此这一步不能靠代码推断跳过。

### 阶段 D：只调 Kx（纯 P）

保持 `Kv=0`：

1. 从目标附近约 20~30px 偏差开始；
2. 若钢球几乎不动，先看是不是卡在静摩擦夹紧的边界——`BALL_CTRL_STICTION_PULSE`
   已经保证只要球没在动、误差超出 `BALL_CTRL_SETTLE_DEADBAND_PX`，命令就至少
   顶到实测阈值，理论上不该再出现"完全不动"；如果还是不动，先重新确认
   `BALL_CTRL_STICTION_PULSE`（3200~4000 脉冲，题目六测的）是否偏低；
3. 若冲过中心很快或持续来回大幅振荡，把 `BALL_CTRL_KX_PULSE_PER_PX` 降低约 30%；
4. 暂不追求完全稳定，只确认能向目标收敛，且不再出现"抬到一半僵住"。

### 阶段 E：加入 Kv

确认速度估计方向正确后，从一个小值开始逐步增加 `BALL_CTRL_KV_PULSE_PER_PXPS`，
目标是压住阶段 D 出现的过冲和振荡。**调 Kv 前先确认球每次都能可靠地动起来**
（阶段 D 的静摩擦夹紧生效）——如果球本身能不能动都不稳定，Kv 调出来的现象会
时好时坏，那是静摩擦没处理好的下游表现，不是 Kv 调参方法有问题。若增大 Kv
后反而在像素噪声上抖动，先降低 `BALL_CTRL_FILTER_BETA` 或 Kv。

### 阶段 F：扩展目标范围

依次测试 `320 → 350 → 290 → 370 → 270`。稳定后再决定是否需要限速或近区
特殊处理。±50mm 目标必须先完成像素到毫米标定，不能直接把 50 当成像素。

### 阶段 G：加入小车运动

先让题目二低速直行，同时保持目标 320；再测试加速、减速和转弯。动态扰动下
若仅靠 X 和球速无法稳定，应进入下一节的后续演进方向，不应继续盲目放大增益。

## 8. 当前结构的物理限制与后续演进

位置模式已经是"用摆杆角度作为控制量"这一步，但仍缺少真实的摆杆角度反馈——
`targetPulse` 是命令值，不是实测值，丝杆间隙、堵转、机械柔性都不会体现在
反馈里。经典 ball-and-beam 的完整状态还包含摆杆角速度。

推荐演进顺序：

1. 当前 α-β + 局部 PD：直接下发绝对目标脉冲，无角度反馈；
2. 用题目六标定出的「脉冲 ↔ 丝杆位移 ↔ 摆杆倾角」换算（见第 9 节）让
   `Kx/Kv` 有物理量纲依据，而非纯凑数；
3. 读取 Emm42 当前位置（`0x36`，注意单位是编码器角度不是脉冲，见第 9 节）
   或增加独立的摆杆角度传感器，把命令值换成实测值再做反馈；
4. 建立串级控制：外环钢球位置 PD 生成目标摆杆角度，内环角度环跟踪；
5. 采集阶跃数据辨识离散模型后，再实现 LQR/LQG。

## 10. Emm42 手册要点与题目六冒烟测试

### 10.1 手册要点与踩坑清单（Emm_V5.0 Rev1.3 全文核对）

| 项 | 结论 |
|---|---|
| 位置模式帧 | `地址+0xFD+方向+速度(2B)+加速度+脉冲数(4B)+相对/绝对+同步+0x6B`（§6.3.1）；`emm42_v5.c` 的 `Emm42_PosControl()` 与手册逐字节一致，协议层无需改 |
| 绝对模式语义 | `相对/绝对`字节 `01`=绝对；**"方向"字节表示目标绝对位置的符号**，脉冲数取绝对值。§6.5 同步示例 `02 FD 00 03E8 0A 0000FA00 01 01 6B` = 绝对运动到 +7200°(64000 脉冲/3200=20 圈) 坐实这点 |
| 脉冲单位 | 随驱动器细分，出厂 16 细分 = **3200 脉冲/圈**；改细分要同步改相关常量 |
| 加速度曲线 | `t2-t1=(256-acc)*50us` 每升 1RPM；`acc=0` = 不用曲线直接按设定速度跑 |
| 位置清零 | `0x0A 0x6D`，"将当前位置角度、位置误差、脉冲数等全部清零"（§6.3.3） |
| 到位判定 | 读 `0x3A`：bit0 使能 / **bit1 到位** / bit2 堵转 / bit3 堵转保护。或把驱动器 `Response` 菜单设为 `Reached`/`Both`，到位后主动回 `地址+FD+9F+6B`（默认是 `Receive` 只回确认） |
| 位置到达窗口 | 默认 `1` = **0.1°**（约 0.9 脉冲 @16 细分），所以 1 脉冲的目标增量就有效，死区不来自驱动器而来自机械间隙 |
| ⚠️ 读位置单位陷阱 | `0x36` 读实时位置返回的是**编码器角度，65536 = 一圈**，不是脉冲数，与位置命令差 **20.48 倍**（`pulses = raw*3200/65536`）。`0x33` 目标位置、`0x37` 位置误差同理 |
| ⚠️ 堵转保护 | 触发条件三条**同时**成立：转速 < `Clog_Rpm`(默认 40RPM) 且 相电流 > `Clog_Ma`(默认 2400mA) 且 持续 > `Clog_Ms`(默认 4000ms)。丝杆低速顶死正好全中。**触发后位置命令返回 `E2` 且电机纹丝不动**——出现"第一次能动、之后怎么发都不动"先查这个，别怀疑帧格式。解除用 `0x0E 0x52`，或用 `0x48 0xD1` 改阈值/关 `Clog_Pro` |
| 极低速手段 | `S_Vel_IS`（`0x4F 0x71`）使能后通讯输入速度缩小 10 倍，发 1RPM 实跑 0.1RPM，手册明确**对位置模式命令同样有效**（§6.3.5）。尚未实现 |
| 位置环 PID | `0x4A 0xC3` 可改，默认 `Kp=62000 / Ki=100 / Kd=62000`。先别动，优先把外环调出来 |
| 原点回零命令组 | `0x9A` 触发（00 单圈就近/01 单圈方向/02 多圈无限位碰撞/03 多圈有限位开关）、`0x93 0x88` 设单圈零点、`0x9C 0x48` 中断回零、`0x3B` 读回零状态、`0x4C 0xAE` 改回零参数。**均未实现**，留作后备 |

> 该手册 PDF 有加密（RC4-128，禁复制），上述结论经解密提取后逐条核对，非凭记忆。

### 10.2 题目六 `ID1 POS` 冒烟测试（API 验证，先于 `BALLCTRL` 完成）

`app/tasks/task6.c`，只操作 `EMM42_ROBOT_LIFT`（ID1），不触碰 ID2/ID3。
`OnEnter` 先 `AppBallControl_RequestStop()`，`OnLoop` 等闭环真正释放 ID1 再开始。

节拍化状态机（每 30ms 轮询拍最多发一帧）：

```
WAIT_BALL_RELEASE → RESET_DISABLE → RESET_WAIT(60ms) → CLEAR_CLOG
  → ENABLE → ENABLE_WAIT(180ms) → ZERO
  → REL(+N 圈)                                     单程，用于标定丝杆导程
  → [REL(-N 圈)]                  T6_RETURN_ENABLE  往返，净位移应回原处
  → [ABS(+MOVE) → ABS(0) → ABS(-MOVE) → ABS(0)]    T6_ABS_TEST_ENABLE
                                                    绝对模式，两次回 0 应同一物理点
  → CYCLE_END（T6_LOOP_FOREVER ? 循环 : DONE）
```

`CYCLE_END → DONE` **不发急停帧**，保持使能让驱动器用保持力矩停在目标位置，
方便拿尺子量行程；K4 退出时才急停失能。

**⚠️ 运动段等待必须覆盖整段运动时间**：位置模式下新的位置命令会**覆盖**尚未走完
的上一条并重新规划，等待太短就表现为"命令发了却几乎没走到位"（2026-07-30 实机
现象：3 圈 @30RPM 需要 6 秒，而当时的停留只有 1.2 秒，所以"9600 脉冲看不见效果"）。
现在 `T6_SEGMENT_WAIT_MS` 由 `T6_TEST_REVS / T6_POS_RPM` 编译期算出理论运动时间
（acc=0 无加减速曲线，时间 = 圈数/转速 分钟），乘 `T6_MOVE_MARGIN_PCT` 余量后再叠加
`T6_DWELL_MS` 观察时间。清零这类瞬时动作仍只等 `T6_DWELL_MS`。**转速越低等待越长**：
10 圈 @30RPM 理论就要 20 秒。彻底的解法是读 `0x3A` bit1 到位标志或让驱动器回
`地址+FD+9F+6B` 到位命令（见 §10.1），当前先用时间兜底。

**所有位置都锚在按 K3 进入本题那一刻的电机位置**：相对模式命令本就以当前实际位置
为起点，绝对模式的原点也是进入本题时才建立的，不存在跨上电或跨一次进出的持久绝对
坐标。反复退出再进入会以当时位置重新置零，单程模式下位移一路累积，量完要手摇回
行程中部再测下一次。这与 `BALLCTRL`（第 5 节）"只在本次上电后第一次启动时清零"
的策略不同——task6 是一次性冒烟测试工具，每次进入都重新标定；`BALLCTRL` 是反复
调参的闭环，需要跨多次 K4 重启保持同一个原点。

可调宏全部集中在 `task6.c` 顶部：`T6_PULSES_PER_REV / T6_TEST_REVS / T6_POS_RPM /
T6_POS_ACC / T6_FIRST_DIR / T6_DWELL_MS / T6_MOVE_MARGIN_PCT / T6_LOOP_FOREVER /
T6_ZERO_ON_ENTER / T6_CLEAR_CLOG_ON_ENTER / T6_RETURN_ENABLE / T6_ABS_TEST_ENABLE`。
**故意不加软件行程限位和软件斜坡**，等量出实际行程后再补一个常量即可。

**已实测数据**：`T6_TEST_REVS=10` 圈（32000 脉冲）对应丝杆行进约 **80mm**，
即导程约 **8mm/圈**（3200 脉冲/圈 → 约 **400 脉冲/mm**）。

### 10.2b 阶梯步长测试（标定钢球静摩擦阈值）

`T6_STEP_TEST_ENABLE=1` 时**完全替代**上面的相对/绝对测试：清零后从水平位置
依次下发 `s_stepTestPulses[]` 数组里的绝对目标，每步等理论运动时间走完后再
停留 `T6_STEP_TEST_DWELL_MS=3000ms` 观察钢球是否开始可见地滚动，然后回到水平
再测下一步，六步测完自动进入 `CYCLE_END`（`T6_LOOP_FOREVER=1` 时整套循环
重测）。数组元素数量须与 `T6_STEP_TEST_COUNT` 保持一致，改步数要两处同改。

**每步的等待时间按该步脉冲数动态计算**（`Task6_StepWaitMs()`），逻辑与
`T6_SEGMENT_WAIT_MS` 相同（理论运动时间 = 脉冲数/每圈脉冲数/转速，换算成毫秒
后加余量百分比，再叠加观察时间），但改成运行时按数组元素现算，因为阶梯测试
的每一步脉冲数不同，不能像原来三项测试那样用编译期常量算一次就够。**这个
改动是吸取了同一坑的教训**：如果固定用一个小的等待时间，步长变大后会重演
"命令被下一帧覆盖、丝杆根本没走到位"的问题（见 §10.2）。

**当前数组值**：`s_stepTestPulses[]={1600,3200,4800,6400,9600,12800}`
（0.5~4 圈）。2026-07-31 用户实测 200~1200 脉冲（≤0.4 圈）全程无反应，且已
确认进题目前摆杆确实水平（排除零点没摆平顶到限位的可能），说明这个量级的
倾角变化确实不足以让球动，于是把步长整体上调到这个更大的范围继续测。

**这测的是与前三项不同的东西**：前三项（相对/往返/绝对）验证的是"丝杆本身
能不能被位置模式大幅度驱动"，早已通过（10 圈=80mm）；阶梯测试测的是"多小的
倾角变化才能真的让球动起来"——摆杆倾角变化本身可能已经完成，但球在凹槽里
自身的静摩擦/滚动阻力可能会让它在小倾角下纹丝不动。这个阈值决定了 `BALLCTRL`
的 `Kx` 下限：如果算出来的脉冲量级长期小于这个阈值，球会在目标附近"死区"里
出不来（丝杆有动作，球却跟不上）。

**用法**：只测 `T6_FIRST_DIR` 方向的响应；要测另一个方向就把 `T6_FIRST_DIR`
改成 `-1` 重新跑一遍。OLED 显示 `STEP +200`/`STEP RET +0` 这类文字，记录哪一步
球开始有肉眼可见的滚动即可，不需要精确测量距离。

**每步测试前都会先解一次堵转保护**（`T6_STATE_STEP_CLEAR_CLOG`）：如果某一步
已经把丝杆顶到机械限位触发了堵转保护，不在下一步之前清掉的话，后续所有
`MoveAbsolute` 都会被驱动器拒绝执行（返回 `E2`）且电机纹丝不动——表现就是
"发的脉冲越来越大，但从头到尾什么反应都没有"，容易被误判成钢球静摩擦特别大，
实际是堵转保护把整个测试锁死了。

⚠️ **如果加了这个修复后仍然全程没反应**（2026-07-31 实测到 1200 脉冲仍无反应），
先不要怀疑钢球摩擦力，大概率是别的问题：
1. **`T6_STATE_ZERO` 建立的"零点"本身不是水平**——如果进入题目六之前摆杆没有
   重新摸平（比如刚跑完 `BALLCTRL` 调参、摆杆停在某个倾角上就直接进了题目六），
   零点会是那个倾斜位置，往 `T6_FIRST_DIR` 方向再走可能立刻顶到机械限位，
   导致后续所有步骤都被堵转保护锁住。**解法：重新上电，先人工摸平再进题目六**；
2. 用当时 `T6_TEST_REVS=10` 圈（32000 脉冲，约 80mm 行程）的大幅度测试重新验证
   一次丝杆能否正常大范围运动（`T6_STEP_TEST_ENABLE` 改回 0），排除机构本身
   卡死或已经顶到端点的可能。

OLED 题名行显示当前阶段与脉冲数（如 `ABS +9600`），串口静默时这是唯一反馈通道。

**判据**：

| 现象 | 结论 |
|---|---|
| `REL+ → REL-` 往返后净位移回原处 | 相对位置模式 API 通 |
| 两次 `ABS +0` 停在同一物理点 | 绝对位置模式 + 原点通，**这是后续外环的前提** |
| 完全不动，且之前顶死过 | 堵转保护，确认 `T6_CLEAR_CLOG_ON_ENTER=1` |
| 动一下停在半路 | `T6_POS_RPM` 太高丝杆带不动，往下调 |
| 方向与预期相反 | 改 `T6_FIRST_DIR`，**别改 `emm42_robot.c` 的方向标定表**（那是 ID1 全局标定，会连带影响 `BALLCTRL`） |

### 10.3 后续可用换算

用 10.2 的实测导程，进而可以把摆杆几何量纲代入外环增益（球杆系统
`a ≈ (5/7)·g·sinθ`）：

```text
sinθ = d / L                          (d = 杆端升降高度，L = 25cm 摆杆长)
pulses = 3200 * L * sinθ / lead        (lead = 8mm/圈，已实测)
```

当前 `BALLCTRL` 的 `Kx/Kv` 仍是纯凑数（第 4 节），有了这个换算之后可以把
增益换算成有物理意义的角度响应，而不是继续拍脑袋试。
