# 钢球 X 位置闭环设计与调试指南

## 1. 当前目标

MCU 复位或重新上电后保持原有 OLED 菜单界面，ID1 处于失能状态。菜单态按下
K4 后启动独立 `BALLCTRL` 线程，以相机中心 `X=320px` 为目标，通过 UART1
速度模式控制 Emm42 ID1 摆杆升降机构；再次在菜单态按 K4 会急停、失能 ID1。

闭环作为后台能力运行，不绑定某一道题。后续题目只需调用：

```c
AppBallControl_RequestTarget(targetPx);
```

即可更新目标位置；调用 `AppBallControl_RequestStop()` 可请求安全退出。题目二、
四、五只控制 ID2/ID3，可与钢球闭环并行；现有题目三直接测试 ID1，进入前会先
等待后台闭环释放 ID1，避免两个控制源争抢同一电机。

## 2. 15Hz 视觉反馈的时间约束

当前上位机下发约 15 帧/秒：

```text
Tvision = 1 / 15s = 0.0667s ≈ 66.7ms
```

`BALLCTRL` 每 10ms 检查一次快照，以降低新帧到达后的响应延迟，但只在
`xSeq` 改变时更新滤波器和控制输出，绝不能把 10ms 误当成视觉采样周期。
速度估计使用相邻有效 X 帧的实际 tick 间隔，并限制在 30~200ms 的合理范围。

控制层把 220ms 保留为硬超时，约等于 3.3 个名义帧间隔。单次 `$X,NA`
或距离最后有效 X 达到 130ms 时只进入 `B:DEG` 软降级：保留滤波状态和 ID1
使能，每 20ms 把命令向 0 RPM 收回最多 2 RPM。连续两帧 `$X,NA` 或 220ms
仍无有效 X 才进入 `B:LOST` 并急停。坏校验/坏格式帧仍只忽略，由这两个时限
兜底。

从 `DEG/LOST` 恢复时要求连续两帧有效 X：第一帧重新初始化滤波位置并把速度
置零，第二帧按真实帧间隔恢复控制，避免长时间断帧后产生速度尖峰。

## 3. 软件结构

```text
UART0 RX ISR
    ↓
module/vision：校验并发布 X + xSeq
    ↓
BALLCTRL 10ms 线程：消费新 xSeq，并在 DEG 中执行 20ms 软减速
    ↓
α-β 滤波：估计 x_filter、v_filter
    ↓
局部 PID：rpm = sign × [Kp·errorForP - Kd·v_filter + Ki·integralError]，直接下发
    ↓
丢球 / 边缘 / 方向保护
    ↓
module/emm42：UART1 整帧互斥 + 5ms 帧间隔
    ↓
Emm42 ID1 速度模式
```

控制命令使用长度为 1 的 FreeRTOS 覆盖队列，只保留最新目标；状态通过临界区
保护的只读快照发布给 OLED。任务层不直接访问闭环内部变量。

## 4. 当前首轮参数

参数集中在 `app/app_ball_control_task.c` 顶部。

| 参数 | 初值 | 作用 |
|---|---:|---|
| `BALL_CTRL_OUTPUT_SIGN` | `+1` | 最终机构/相机极性，方向错时改成 `-1` |
| `BALL_CTRL_KP_RPM_PER_PX` | `0.18` | 位置误差到 RPM 的比例增益（以控制源码当前值为准） |
| `BALL_CTRL_KD_RPM_PER_PXPS` | `1.6` | α-β 速度制动增益（以控制源码当前值为准） |
| `BALL_CTRL_KI_RPM_PER_PXSEC` | `0.05` | 低速小误差区的静摩擦补偿积分增益 |
| `BALL_CTRL_I_OUTPUT_LIMIT_RPM` | `2.0` | I 项单独允许贡献的最大 RPM，不是总输出限速 |
| `BALL_CTRL_I_DEADBAND_PX` | `1.0` | I 项在此范围内清零，避免中心抖动 |
| `BALL_CTRL_I_ENABLE_ERROR_PX` | `12.0` | I 项仅在此误差范围内工作 |
| `BALL_CTRL_I_ENABLE_VELOCITY_PXPS` | `10.0` | I 项仅在低于此速度时工作 |
| `BALL_CTRL_EMM_ACC` | `0` | Emm42 速度模式立即生效，不加驱动器速度曲线 |
| `BALL_CTRL_FILTER_ALPHA/BETA` | `0.70/0.08` | α-β 位置/速度滤波参数 |
| `BALL_CTRL_VISION_DEGRADE_MS` | `130ms` | 无有效 X 进入软降级的阈值 |
| `BALL_CTRL_VISION_TIMEOUT_MS` | `220ms` | 无有效 X 进入 LOST 的硬超时 |
| `BALL_CTRL_NA_LOST_COUNT` | `2` | 连续 NA 进入 LOST 的帧数 |
| `BALL_CTRL_DEGRADE_RPM_STEP` | `2` | DEG 每 20ms 向 0 RPM 回退的步长 |

当前使用局部 I 项补偿静摩擦，不替代摆杆位置内环。I 只在新有效视觉帧、
`1px<|原始误差|≤12px` 且 `|速度|≤10px/s` 时按真实帧间隔积累；I 输出单独限制
为 `±2RPM`。目标改变、误差跨过零点、进入 1px 死区、速度过高、进入 DEG/LOST、
K4 停止、边缘或方向故障都会立即清零，避免旧积分持续推动摆杆。

## 5. OLED 状态

菜单右侧第四行显示闭环状态：

| 显示 | 含义 |
|---|---|
| `B:OFF` | 未占用 ID1，上电默认状态 |
| `B:START` | 正在失能复位、使能并等待驱动器稳定 |
| `B:WAIT` | ID1 已使能，等待连续两帧有效 X |
| `B:RUN` | 正常闭环 |
| `B:HOLD` | 连续 500ms 满足中心位置与低速度条件，仍继续保持闭环 |
| `B:DEG` | 单次 NA 或短时断帧，ID1 保持使能且命令正在软降到 0 RPM |
| `B:LOST` | 连续两帧 NA 或有效 X 超过 220ms，ID1 已急停 |
| `B:DIR!` | 首次方向检查发现误差持续扩大，需翻转输出极性 |
| `B:EDGE!` | 钢球坐标到达画面安全边界 20/620px |

故障态会急停并保持 ID1 使能，以保持当前摆杆位置。当前不再使用软件估算行程
限制，调试时须确认机构物理限位安全；菜单态按一次 K4 请求急停
并失能，状态回到 `B:OFF` 后才可再次启动。

## 6. 上车调试顺序

### 阶段 A：只验证视觉

不按 K4，连续观察 OLED：

1. 球在中心时 `X≈320`；
2. 向画面右侧移动时 X 增大，向左侧移动时 X 减小；
3. 静止波动先记录峰峰值；
4. 连续运行 10 分钟，确认无跳变、乱码和持续漂移；
5. 制造单次 `NA`，确认只进入 `B:DEG`，连续两次 `NA` 才进入 `B:LOST`；
6. 恢复识别后确认第一帧不产生新的闭环输出、第二帧回到 `B:RUN`，没有突然
   反向大 RPM。

未通过本阶段时不要使能 ID1。

### 阶段 B：确认最终控制方向

1. 人工把摆杆调到近似水平，钢球放在 `X=280~290` 或 `X=350~360`；
2. 一只手准备断电，按 K4；
3. 确认 `B:START → B:WAIT → B:RUN`，并观察钢球误差是否开始减小；
4. 若误差变大或出现 `B:DIR!`，按 K4 停止，把
   `BALL_CTRL_OUTPUT_SIGN` 从 `+1` 改为 `-1` 后重新编译；
5. 方向未确认前不增加 Kp、不提高最大 RPM。

ID1 角色层只能说明“正 RPM＝连杆向下”，最终钢球方向还取决于连杆安装在摆杆
哪一端以及相机图像是否镜像，因此这一步不能靠代码推断跳过。

### 阶段 C：只调 Kp

保持 `Kd=0`、`Ki=0`，PID 输出不做最大 RPM 或斜率限制：

1. 从目标附近约 20~30px 偏差开始；
2. 用“最低有效 RPM ÷ 30px”估算 Kp 起点，现有 `0.08` 作为基线；
3. 若钢球几乎不动，每次将 Kp 增加约 15%~20%；
4. 若冲过中心很快或机构持续来回运动，将 Kp 降低约 20%；
5. 记录“刚好能可靠克服静摩擦”的最小 Kp 和 RPM；
6. 暂不追求完全稳定，只确认能向目标收敛。

### 阶段 D：增加 Kd

确认速度估计方向正确后，从 `0.005 RPM/(px/s)` 开始，每次增加 `0.005`，
目标是把首次过冲压到 3~5px 并消除第二次穿越。若电机命令被像素噪声带着
抖动，先降低 β 或 Kd，不用继续增大 Kd 或用更大位置死区掩盖问题。浮点输出
在下发前采用四舍五入，不再直接截断小于 1 RPM 的有效命令。

### 阶段 E：最后加入受保护 I 项

先确认仅 PD 已能在目标附近减速、不会持续发散，再从 `Ki=0.05`、I 输出上限
`2RPM` 开始。只从目标两侧静止偏差约 3~5px 开始测试：若 4~5 秒仍无法克服
静摩擦，Ki 每次增加约 50%（`0.05 → 0.075 → 0.11 → 0.16`）；若刚移动就穿过
中心或中心附近缓慢漂移，先将 Ki 减半，再把 I 上限降为 `1RPM`。若频繁正反蹭动，
把 I 死区由 1px 提到 2px。倾斜后持续加速并非静摩擦问题，应将 Ki 回到 0。

### 阶段 F：提高速度和目标范围

依次测试 `320 → 350 → 290 → 370 → 270`。每个方向重复 10 次，至少 9 次
达到“过冲不超过 5px，3 秒内进入目标 ±5px，且速度不超过 10px/s 并持续
500ms”后，再决定是否恢复最大 RPM、斜率或近区限速。±50mm 目标必须先完成
像素到毫米标定，不能直接把 50 当成像素。

### 阶段 G：加入小车运动

先让题目二低速直行，同时保持目标 320；再测试加速、减速和转弯。动态扰动下
若仅靠 X 和球速无法稳定，应进入下一节的串级控制，不应继续盲目放大 PID。

## 7. 当前结构的物理限制与后续算法

经典 ball-and-beam 的完整状态至少包含钢球位置、钢球速度、摆杆角度和摆杆角速度。
当前只有钢球 X，而执行量是电机 RPM；RPM 还会积分成摆杆角度，所以单层位置 PID
只能作为低速验证和系统辨识起点，不能等同于完整状态反馈。

推荐演进顺序：

1. 当前 α-β + 局部 PID：I 仅补偿低速小误差的静摩擦，且输出限制为 ±2RPM；
2. 读取 Emm42 当前脉冲位置，或增加摆杆角度/高度传感器；
3. 建立串级控制：外环钢球位置 PD 生成目标摆杆角度，内环角度 PID 跟踪；
4. 采集阶跃数据辨识离散模型后，再实现 LQR/LQG；
5. 若仍无法同时满足速度和过冲指标，优先增加摆杆角度或 ID1 位置内环，而非增大 I。

## 8. 可参考的开源实现

- [`giusenso/Ball-Balancing-PID-System`](https://github.com/giusenso/Ball-Balancing-PID-System)：
  MIT 许可，采用视觉反馈、数字 PI-D 和串口
  执行模块分层，适合参考“视觉/滤波/控制/执行分离”的结构；硬件是二维舵机平台，
  增益和执行接口不能直接照搬。
- [`yaswhar/Ball-Beam-Control`](https://github.com/yaswhar/Ball-Beam-Control)：
  包含系统辨识、内环稳定、PID/2DOF-PID 和
  MATLAB/Simulink 模型，适合后续根据实测数据建模；不是可直接烧录到 MSPM0 的固件。
- [ARM CMSIS-DSP PID](https://arm-software.github.io/CMSIS-DSP/latest/group__PID.html)
  提供 Q15/Q31/F32 PID 实现，但本仓库已有满足当前需求的纯 C
  算法层。当前关键不在替换 PID 函数，而在补足摆杆状态、超时和执行器约束。
- [增强状态估计 + 离散 LQR 研究](https://doi.org/10.1109/ICIEA.2011.5975793)
  同时估计钢球位置/速度和电机角度/角速度；在只有 X 的条件下直接套用论文
  增益没有物理意义。
